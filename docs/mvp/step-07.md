## 実装内容

### 1. App.tsx

メインアプリケーションコンポーネント。

#### 構成

```
<App>
├── <header> - アプリタイトル
├── <main>
│   ├── エラー表示（条件付き）
│   ├── <FileSelector>
│   ├── <ModelSelector>
│   ├── <ProgressBar>（処理中のみ）
│   ├── 開始ボタン（結果なし・非処理中のみ）
│   └── <ResultViewer>（結果あり時）
│       └── 新規ファイル / 再実行ボタン
└── <footer> - バージョン表示
```

#### 処理フロー

1. `onMount` で `whisper.loadModels()` を呼び出し
2. ファイル選択 → `whisper.setFile()`
3. モデル選択 → `whisper.selectModel()`
4. 開始ボタンクリック → `whisper.startTranscription()`
5. 結果表示 / エラー表示

#### 開始ボタンの有効条件

- ファイルが選択されている
- モデルが選択されている
- 処理中でない

### 2. index.tsx / index.css の確認

- index.tsx: `solid-js/web` の `render` でAppをマウント（変更なし）
- index.css: Tailwindディレクティブとベーススタイル（変更なし）
- App.css: 不要（全スタイルは Tailwind CSS で対応）

## 注意: whisper-rs 0.15.1 abort callback バグ

手動確認時に文字起こしがエラー -6（"failed to encode"）で失敗する問題が発生。原因は whisper-rs 0.15.1 の `set_abort_callback_safe` 内のトランポリン関数の型パラメータ不一致による未定義動作。

クロージャを事前に `Box<dyn FnMut() -> bool>` にボックス化して渡すことで回避。詳細は `CLAUDE.md` の「既知の問題・ワークアラウンド」を参照。

## 注意: ダッシュボード機能との関係

[ダッシュボード機能](../features/dashboard.md) を実装する場合、本ステップの構成は以下のように変更されます：

| MVP構成 | ダッシュボード導入後 |
|--------|-------------------|
| App.tsx が単一画面 | App.tsx はルーティング設定のみ |
| 直接コンポーネント配置 | サイドバー型レイアウト |
| 起動時に文字起こし画面 | 起動時にダッシュボード |

MVP の App.tsx の内容は `src/pages/Transcription.tsx` に移行し、`/transcription` パスで表示されます。
